# 三明文旅乐园 · 桌宠浮窗

把三明文旅 IP「明奇奇」做成一只贴在 WorkBuddy 输入框上方的透明浮窗：左边轮播三元区景点照片和一句话介绍，右边明奇奇会呼吸、会跳跃翻滚，点它还能弹出设置面板。不想看照片卡片时，一键切精简模式 —— 只留宠物，头顶一条小标签轮播三元区的景区、美食、特产。

> 说明：WorkBuddy 输入框右上角那只「成长伙伴」是服务端下发的运营位（shadow DOM 渲染），本地换图不会生效——所以这套方案不走皮肤，改成独立浮窗，效果一样是「长在输入框上」。

## 一、安装（给其他用户）

### 1. 拿到安装包

把整个目录打包发出去即可，目录里不要少这三样：

```
pet-overlay.ps1          主程序
assets\frames\*.png      宠物动作帧（110 张）
data\                     轮播文案 + 景点照片
tools\                    本地知识库检索器 + SAG 原生 exe
install.ps1              一键安装
```

打包命令（发之前执行一次）：

```powershell
Compress-Archive -Path pet-overlay.ps1,assets,data,tools,install.ps1,uninstall.ps1,README.md `
  -DestinationPath 三明文宠-1.9.19.zip -Force
```

（`data\config.json` 是本机运行状态，打包前可以先删掉，安装时会保留用户自己的设置。）

### 2. 安装

解压后在该目录里打开 PowerShell，运行：

```powershell
powershell -ExecutionPolicy Bypass -File install.ps1
```

安装脚本会：

- 复制到 `%LOCALAPPDATA%\SanmingPetOverlay`（可用 `-Target` 改）
- 在桌面建「三明文宠」快捷方式（图标是明奇奇头像，不是 PowerShell 蓝底图标）
- 立刻启动一次

常用参数：

| 参数 | 作用 |
|---|---|
| `-Autostart` | 同时设开机自启（扔一份快捷方式到启动文件夹） |
| `-NoLaunch` | 只装不启动 |
| `-Target D:\Pet` | 装到指定目录 |

### 3. 关掉、再打开

关掉和卸载是两件事：

| 你想要 | 怎么做 |
|---|---|
| 今天不想看见它 | 点宠物 → 设置面板右下角「关闭浮窗」→ 进程直接结束，桌面干净，任务栏不留托盘图标 |
| 再打开 | 双击桌面「三明文宠」；Windows 11 也能在开始菜单直接搜「三明文宠」（安装时在开始菜单也建了一份） |
| 开机不想让它自己冒出来 | 删 `shell:startup` 里的「三明文宠.lnk」，或重装时不勾「开机自动启动」 |
| 彻底不要了 | 见下面「4. 卸载」 |

> 关掉只是结束进程，绑过的文件夹、模型设置、宠物位置都存在 `data\` 里，下次打开原样恢复。
> 双击两次不会叠出两只：脚本里加了单实例锁，第二次启动会直接退出。

### 4. 卸载

```powershell
powershell -ExecutionPolicy Bypass -File uninstall.ps1          # 删快捷方式+结束进程
powershell -ExecutionPolicy Bypass -File uninstall.ps1 -Purge   # 连目录一起删
```

### 系统要求

- Windows 10 / 11（浮窗基于 WPF + 分层窗口，Windows 专属；Linux / macOS 需要另一套实现）
- PowerShell 5.1 以上即可，装了 PowerShell 7 更好
- 首次运行如果被 SmartScreen 拦，选「更多信息 → 仍要运行」

## 二·五、知识库（SAG 本地检索）

绑一个文件夹（放笔记、规范、周报、资料都行）就是一座知识库，问中文问题直接回到原文段落 + 第几行。**默认不联网、不要 Key、不调用任何大模型**；想让它读成一段答案的话，看下面「模型设置」。

用法：

1. 按 `Ctrl+Alt+K`（或点宠物 → 设置面板 → 「知识库」行）打开知识库窗口
2. 点右上角那个实心墨绿胶囊「＋ 绑定文件夹」（鼠标移上去会变亮），选一个目录；索引建好后这里显示「n 个文件夹 / m 个文件」。这行本身就是折叠开关——浅绿胶囊 + 深绿实心三角 + 末尾「收起 / 展开」两个字，一眼能看出可以点：三角朝下（▼ 收起）时列表展开，朝右（▶ 展开）时列表收起，鼠标移上去整块变深绿。列表限高 7 行左右，收起后结果区自动上移，不会被列表挤没
3. 在搜索框里提问，回车或点「检索」，结果卡片显示文件名 + 第几行 + 命中段落（关键词描绿）
4. 点结果卡片不再直接甩出整份文档，而是弹一个 560×620 的 **「段落详情」窗**：标题写文件名，副标题写章节和第几行到第几行，正文把这一次命中的完整段落铺开（结果卡上只显示前 340 字，这里是全文），命中的关键词照样描绿。想在原文里前后翻，点窗子右下角的「在 VS Code 打开原文」跳到那一行（没装 VS Code 就用记事本打开）。

问法不用太正经。问「三元区有什么好玩的」，检索器会自动把「好玩」翻成资料里的正式说法 **景区 / 景点 / 旅游** 再去找，问「有什么好吃的」补 **美食 / 小吃**；状态栏会多显示一段 `＋景区/景点/旅游`，告诉你是补了哪些词才命中的，这几个词在正文里也会描绿。
排序上还多两层判断：段落所在章节本身就是景区 / 美食 / 交通题材的，往前提；通篇写着「不适用」的名片、荣誉、名单类模板（比如「全国和谐社区建设示范城区」），往下压——它们字段是空的，答不了旅游问题。

卡片里显示的文字会先洗掉源文件自带的 markdown 标记（`**`、`##`、`|`、列表符这些），再给命中的关键词描绿，不会满屏都是星号。接了答案模型之后，最上面那张答案卡是按 markdown 渲染的：小标题、加粗、列表、行内代码都按格式显示，`[1][2]` 这类引用编号显示成绿色小标记。

### 两跳检索

问「1 号高炉冷却壁水温差超标的那张处理单后来怎么处理的」，只靠关键词只能翻到那张点检记录，看不到后续。所以检索分两步：

- **第一跳**：正常 BM25 召回
- **第二跳**：从命中段落里挑出**单号 / 型号**（`GX-2026-0451` 这种字母和数字都有的长串）当线索，再检索一次
- 第二跳的结果卡片右上角带一枚绿色徽章「第二跳 · 由 GX-2026-0451 串到」，底栏也会写「第二跳 +n」

企业资料里真正要多跳才能答的问题，多半是靠单号、设备号、型号串起来的，而不是语义相近——所以纯词法也能做到，不需要任何模型。

⚠️ 线索词只认这种带数字的长串。早先的版本还拿「标题里的词」「正文里的普通实词」当过线索，结果「要求」「第17章」这类词把毫不相干的文档全捞了进来：问高炉会跳出文旅大全，问三元区旅游又跳出高炉台账，两边互相串味。现在的取舍是**宁可少串一跳，也不串错**。

### 同义词表

`data\检索别名.json` 可以自己加。命中左边任一说法时，右边的说法也会一起拿去召回（反过来也生效）：

```json
{ "数据中台": ["数据中台", "中台", "数据平台"] }
```

改完保存就生效，不用重启。

### 索引体积

窗口右下角会显示「索引 0.2 MB · 5 文件」。如果你绑过一个大目录又移除了，SAG 只做逻辑删除、磁盘不会立刻还给你（实测一个 200 KB 的库能被撑到 156 MB），这时那里会显示橙色的「可收缩」，点一下就能回收。

### 增量更新

改完文件不用管，程序每 10 分钟比对一次文件时间和大小，有变化就在后台重建索引（SAG 自带的 watch 也会补一刀）。

### 模型设置（可选：接自己的 LLM）

默认**一个模型都不接**，检索照常能用。如果你手上有本地或云端的 OpenAI 兼容模型，可以让它把命中的原文读成一段答案。

入口：知识库窗口标题栏右上角那个 **「模型 · 关」** 胶囊，点开就是设置窗。也可以直接改 `data\模型.json`。

两块配置：

| 区块 | 作用 | 不配的后果 |
|---|---|---|
| 答案模型 | 检索完在结果最上面多一张「答案」卡，每条事实后面标 `[1][2]`，对应下面第几张原文卡 | 只有原文卡，和以前一模一样 |
| JEV 语义增强 | 把 SAG 官方的决策模型接进来（需自己部署） | 浮窗检索不受影响，它本来就不依赖 JEV |

**答案模型**填三样：服务地址、模型名、密钥（本地模型不用填密钥）。点「测试连接」会去 `GET /v1/models` 验一下，能列出模型名就说明通了。

服务地址填到 `/v1` 就行，程序自己补 `/chat/completions`：

| 你手上的 | 服务地址 | 模型名 |
|---|---|---|
| Ollama | `http://127.0.0.1:11434/v1` | `qwen2.5:7b`（先 `ollama pull`） |
| LM Studio | `http://127.0.0.1:1234/v1` | 界面里显示的那个名字 |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| vLLM / llama.cpp server | `http://127.0.0.1:8000/v1` | 启动参数里指定的 model |

下面那三枚胶囊（Ollama 本地 / LM Studio / DeepSeek 云）只是快捷填充，点一下把地址和常见模型名写进去，模型名仍要自己核对。

⚠️ **保存不等于启用**：填完地址、模型名、密钥，点右下角「保存」只是把它们写进 `data\模型.json`；真正让浮窗去调模型，是右上角那枚 **「答案模型」开关** —— 灰底「关」要变成绿底「开」。开关关了，配置存得再全也只会走纯检索。
保存成功后，「测试连接」右边会出现一行绿字告诉你当前状态：开着的写 `✓ 已保存 时:分:秒 · 答案模型开（模型名）`，没开的会直接提醒「地址存好了，但右上开关还关着」。看到这行字才算保存成功，没看到就是这次点击没落上，再点一次。

**JEV 语义增强**要你自己下载部署——它是 SAG 官方那个小的相关性打分模型，不吃普通聊天模型，别把 LLM 的地址填进去。填好点「写入 SAG」，等价于：

```powershell
sag config --url <地址> --model <名> --auth none|bearer --key-stdin
```

⚠️ 这会改 SAG 的**全局**配置，不只影响本浮窗。写完右上角胶囊会变成「已配置」——它读的是 `sag status`，不是本地 json，所以状态是真实生效的。

**几条约束是写死的，不是可选项**：

- 只喂命中的前 5 段、每段截 700 字，免得一次把整个文件塞进去烧额度
- 提示词强制「只能依据这些片段作答，片段里没有就直说没查到」，并要求每条事实标来源编号
- 模型连不上就静默降级回纯检索，不弹窗、不卡住
- 生成放在后台线程，7B 模型吐 20 秒字浮窗也不会僵；超过 150 秒直接放弃
- 答案是**参考**，下面永远附原文卡片——编号对得上才可信

**隐私**：本地模型数据不出本机；接云端接口意味着你库里的原文会发到对方服务器，内部资料自己掂量。

配置存在 `data\模型.json`，密钥是明文（PasswordBox 只是输入时遮挡），别把整个目录发给别人。

### 边界

- **默认只做检索**：不开模型时返回的就是原文段落本身，绝不编造。开了答案模型才会多一张答案卡，而答案里每条都带编号，必须对得上下面的原文卡才可信
- **PDF / Word / Excel** 会被 SAG 转成文本建索引，但卡片只能给出位置，没有可预览的纯文本（点了用系统程序打开）
- FTS 索引是按 jieba 词存的，**库里没出现过的新词**要等索引重建后才能搜到；实在搜不到先确认文件确实在绑定的目录里

实现说明：

- 索引和分词来自 [SAG](https://github.com/Zleap-AI/SAG-Wiki)（SQLite FTS5 + jieba 词表，BM25 打分），建库 0 次模型调用
- SAG 的语义检索要走 JEV 判定（云端收费、数据出境）。本浮窗的检索**不依赖**它，只走纯本地 FTS；JEV 只在设置窗里给了一个 `sag config` 写入入口，供你自己部署后使用
- 检索器是 `tools\kb-search.py`，读 `%APPDATA%\com.sag.desktop\sag.sqlite` 里的索引
- 分词必须逐字做最长匹配：SAG 索引里存的是 jieba 切好的词，「冷却壁」在库里被切成 `冷却`+`壁`，整串去查必然 0 命中
- 排序 = 正文命中数 + 标题命中（权重加倍）+ 单号串联（精确命中额外加分），最后才用 BM25 微调
- 索引库位置：`%APPDATA%\com.sag.desktop\sag.sqlite`；原文件一个字节都不动，删掉索引库即可彻底清空
- 绑了桌面 / 下载 / 整个用户目录这种大目录会先弹确认框；索引在后台跑，跑完后窗口里的文件数会自己刷新

依赖：

- **Python 3**（检索器用标准库，装哪个都行）。脚本会自动找 `python` / `python3` / `py`
- `tools\sag\sag.exe`（SAG 0.3.11 原生版，42.8 MB，随包附带，不需要 Node）


宠物每隔 5~11 秒自己动一次：四成概率播连帧动画（跃起、翻滚、冲刺），六成摆一个单帧姿势（挥手、叉腰、鞠躬、抱抱…）。

空白区域鼠标穿透，不会挡住下面的输入框和按钮。

## 三、目录结构

```
pet-overlay.ps1              主程序（WPF 分层窗口）
install.ps1 / uninstall.ps1  安装、卸载
assets\frames\               动作帧，命名 <宠物>-<动作>.png
data\三明三元区轮播.json      18 条轮播（6 景点 × 3 条）
data\三元区速览.json          12 条短句（景区 / 美食 / 特产），关掉卡片后头顶标签循环播
data\photos\                 景点照片 520×390
data\config.json             运行时生成：宠物 / 轮播开关 / 景区卡片 / 跟随 / 位置
data\检索别名.json            同义词表，可自己加（例：数据中台 → 中台 / 数据平台）
data\模型.json                可选：答案模型 / JEV 配置（默认全关，见「模型设置」）
tools\kb-search.py           本地检索器（读 SAG 索引，两跳召回）
tools\sag\                    SAG 0.3.11 原生 exe，负责建索引 / 增量更新
```

知识库相关文件（程序自己维护，不用管）：

```
%APPDATA%\com.sag.desktop\sag.sqlite   SAG 索引库（多绑一个文件夹就往里加一份索引）
%TEMP%\sanming-kb-sag.log              sag add 的输出日志
```

`config.json` 长这样，可以直接手改：

```json
{ "pet": "mingqiqi", "carouselOn": true, "showCard": true, "follow": true, "left": null, "top": null }
```

- `pet`：`mingqiqi` / `minglingling` / `mingbaobao`
- `showCard`：`true` = 常规模式（560×348，左边照片卡片）；`false` = 精简模式（252×300，只留宠物 + 头顶标签）
- `follow`：`true` = 跟着 WorkBuddy 窗口贴边；`false` = 停在 `left` / `top`
- WorkBuddy 最小化或没开时，浮窗会贴到桌面右下角，不会消失

## 四、常见问题

**浮窗看不见？**
WorkBuddy 最小化时会落到桌面右下角，先看那儿。还看不到就看日志：`%TEMP%\sanming-pet-overlay.log`。

**宠物不跟随了？**
拖动过就会自动关掉跟随，在设置面板点「贴边跟随」重新打开。

**浮窗拖到屏幕最右边，打开设置面板会被挤没吗？**
不会了。设置面板比精简态宽 308px，展开时程序会把窗口往左收，保证右边界不出屏；收起后再回到展开前那个点，宠物重新贴回屏幕右边。多屏也按窗口所在那块屏算，不会算到隔壁屏去。

**照片打不开？**
详情页是外链新闻 / 百科，个别站点可能失效，改 `data\三明三元区轮播.json` 里对应条目的 `url` 即可（不写 `url` 就用脚本里内置的映射）。

**知识库搜不到东西？**
先看窗口底部那行状态：没绑定就点「+ 绑定文件夹」；显示「建索引中」就等它跑完。仍不行就查 `%TEMP%\sanming-kb-sag.log`，再确认 python 是否可用 —— 命令行跑 `python tools\kb-search.py --roots` 能打印出当前已绑的目录和文件数。

**问了个问题，只有第一跳的结果？**
第二跳只认单号 / 型号（像 `GX-2026-0451`、`XG-2019-A`），普通词不再当线索了，所以只出第一跳是正常的、不是坏了。想让两段内容互相关联，优先在 `data\检索别名.json` 里加一组同义词，往往比第二跳更快见效。

**改了文件，知识库还是旧内容？**
程序每 10 分钟自查一次，有改动会在后台重建；等不及就手动跑一遍：

```powershell
.\tools\sag\sag.exe add "你的目录" --timeout 600
```

**索引库越来越大？**
绑过的大目录移除后只是逻辑删除，磁盘不会立刻还回来。看知识库窗口右下角：显示橙色「可收缩」就点一下；也可以命令行 `python tools\kb-search.py --stats` 看体积、`--vacuum` 回收。

**绑错目录了？**
知识库窗口里每个目录右边有「移除」，点一下只删索引，原文件不动。

**能不能直接替换 WorkBuddy 输入框上那只机械猫？**
不行。那只猫是 WorkBuddy 服务端下发的运营位，HTML 在服务端，本地只换图片资源不会生效（实测重启后无变化）。

**能不能只在 WorkBuddy 里用、不常驻？**
可以把它当 WorkBuddy skill 的脚本调用（`sanming-pet-park` 技能），但那样只有 WorkBuddy 在跑、且由它触发时才出现；想要随时贴边，还是用这个独立浮窗稳。
